  Каждый блок = видимый промежуточный результат
==============================================================

КОНТЕКСТ
--------
MindLint — Telegram-бот для логического анализа решений
и обнаружения самообмана. Пользователь отправляет
утверждение/решение → бот анализирует через LLM:
декомпозиция на факты/причины/условия, поиск 5 паттернов
логических дефектов. Бот НЕ даёт советов — только анализ.

Структура папок создана (все файлы — пустые заглушки).


==============================================================
БЛОК 1. Фундамент — конфигурация и запуск пустого бота
==============================================================

ЦЕЛЬ: Бот запускается и отвечает на /start приветствием.

РЕЗУЛЬТАТ: Отправить /start → получить приветствие.

ЗАДАЧИ:
  1.1  .env.example — шаблон переменных окружения
       BOT_TOKEN, GROQ_API_KEY, LLM_PROVIDER=groq,
       LLM_TEMPERATURE=0.3, GROQ_MODEL, ADMIN_IDS,
       DATABASE_URL, LOG_LEVEL

  1.2  app/config.py — Settings(BaseSettings) через pydantic-settings
       Все переменные из .env с типизацией
       model_config = SettingsConfigDict(env_file=".env")
       Глобальный экземпляр settings = Settings()

  1.3  app/utils/logging_config.py — функция setup_logging(level)
       Формат: время, уровень, модуль. Один раз при старте.

  1.4  app/bot.py — Bot + Dispatcher
       Bot(token=settings.BOT_TOKEN), Dispatcher()
       Функция register_routers(dp) — пока только start_router

  1.5  app/handlers/start.py — роутер /start и /help
       /start → приветствие: что такое MindLint, как пользоваться
       /help → краткая справка по командам

  1.6  main.py — точка входа
       setup_logging(), создание бота, dp.start_polling(bot)

ПРОВЕРКА:
  pip install -r requirements.txt
  cp .env.example .env   # заполнить BOT_TOKEN
  python main.py
  → /start → приветствие
  → /help → справка
  → В консоли логи без ошибок

==============================================================

ЦЕЛЬ: Бот умеет отправлять текст в LLM и получать ответ.

РЕЗУЛЬТАТ: Тестовый запрос к Groq → получить анализ в консоли.

ЗАДАЧИ:

  2.2  app/services/llm/groq.py — Groq (бесплатный)

       Обработка ошибок с логированием

  2.3  app/services/llm/openai.py — OpenAI
       AsyncOpenAI(api_key=...), аналогичный интерфейс

  2.4  app/services/llm/anthropic.py — Anthropic

  2.5  app/services/llm/factory.py — фабрика провайдеров

  2.6  app/prompts/system_prompt.txt — чистый системный промпт
       Извлечь из DOCS/mindlint_system_prompt.md
       Без markdown-обёрток — только инструкции для LLM

ПРОВЕРКА:
  Тестовый скрипт: создать провайдер через фабрику,
  отправить утверждение → получить анализ.
  Переключить LLM_PROVIDER в .env → другой провайдер.


==============================================================
БЛОК 3. Основной цикл — анализ текста через бота
==============================================================

ЦЕЛЬ: Пользователь пишет текст → бот показывает "печатает..."
→ отправляет логический анализ от LLM.

РЕЗУЛЬТАТ: ★ ПЕРВЫЙ РАБОЧИЙ MVP ★
Текст → анализ логики в Telegram.

ЗАДАЧИ:
  3.1  app/utils/typing_action.py — индикатор набора
       Контекстный менеджер на базе ChatActionSender
       Показывает "typing..." пока LLM генерирует

  3.2  app/utils/text_formatter.py — форматирование
       escape_markdown_v2(text) — экранирование MarkdownV2
       split_message(text, max_len=4096) — разбивка длинных

  3.3  app/services/analysis.py — сервис анализа
       class AnalysisService:
         загрузка промпта из файла → вызов LLM → форматирование
       Обработка ошибок с user-friendly сообщением

  3.4  app/handlers/analyze.py — основной хендлер
       Router(), фильтр F.text (любой текст, не команда)
       Показать typing → AnalysisService → отправить результат
       Длинный ответ → разбить на части
       ВАЖНО: роутер регистрируется ПОСЛЕДНИМ (catch-all)

  3.5  Обновить app/bot.py — подключить analyze_router последним

ПРОВЕРКА:
  python main.py
  → "Я не могу уволиться, потому что сейчас не время"
    → Бот: "печатает..." → логический разбор
    → Декомпозиция, паттерн D, уточняющий вопрос
  → "Я учу Python, потому что востребовано и нравится"
    → Бот: логика корректна (без ошибок)
  → Длинный ответ разбивается на части

==============================================================
БЛОК 6. Паттерны мышления — /patterns
==============================================================

ЦЕЛЬ: Бот показывает повторяющиеся паттерны логических
ошибок пользователя.

РЕЗУЛЬТАТ: /patterns → визуальная сводка паттернов.

ЗАДАЧИ:
  6.1  app/services/pattern_tracker.py — детектор паттернов
       Загрузка всех анализов пользователя
       Подсчёт 5 паттернов в ответах LLM:
         A — Подмена причины чувством
         B — Ложная необходимость
         C — Циклическая логика
         D — Неопределённое условие
         E — Универсальное оправдание
       Формирование сводки: частота, тренды

  6.2  Обновить app/database/models/analysis.py
       Добавить detected_patterns (JSON список)
       Заполняется при анализе (парсинг ответа LLM)

  6.3  app/handlers/patterns.py — хендлер /patterns
       Сводка: "Ваши паттерны за N анализов:"
       Визуализация: ███░░ Подмена причины — 3 раза
       Мало данных (< 3) → "Нужно больше анализов"

ПРОВЕРКА:
  5+ анализов → /patterns
  → Сводка с визуализацией частоты
  → При малом кол-ве — информативное сообщение
